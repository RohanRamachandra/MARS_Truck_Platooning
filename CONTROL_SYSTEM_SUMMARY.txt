1. CONTROL SYSTEM ARCHITECTURE
------------------------------

   A. Distance Policy (Spacing Control)
      - Formula: desired_distance = T_GAP * velocity + D_MIN
      - T_GAP = 0.6 seconds (time headway)
      - D_MIN = 2.0 meters (minimum distance)
      - Implemented in: calculateDesiredDistance()
      - Called by: updateControl() every 100ms
      
   B. PD Controller (Acceleration Control)
      - Proportional gain: KP = 0.5
      - Derivative gain: KD = 0.1
      - Error: distance_error = current_distance - desired_distance
      - Error rate: error_derivative (approximated from distance change)
      - Control output: u = KP * error + KD * error_rate
      - Implemented in: computePDControl(error, errorRate)
      
   C. Feedforward Control
      - Predecessor acceleration tracking (0.0 for baseline)
      - Feedforward term: 0.5 * predecessor_acceleration
      - Combined with PD output for smoother response
      - Reduces steady-state error and improves tracking
      
   D. Acceleration Bounding
      - Maximum acceleration: 2.0 m/s²
      - Jerk limiting: maximum 1.0 m/s³ (acc change rate)
      - Ensures smooth, realistic vehicle dynamics
      - Implemented in: boundAcceleration(desiredAccel)
      
2. CONTROL LOOP INTEGRATION
----------------------------

   Scheduler Task: 100ms cycle (10Hz update frequency)
   ├─ handleCommLoss() - Check for communication timeouts
   ├─ simulateVehicleState() - Update vehicle dynamics
   └─ updateControl(0.0) - Compute and apply control (followers only)
   
   Control Update Sequence:
   1. Calculate desired distance from velocity and gap policy
   2. Compute distance error (actual vs desired)
   3. Calculate PD control output
   4. Add feedforward from predecessor acceleration
   5. Bound acceleration (hard limits + jerk)
   6. Update velocity: v_new = v + accel * dt
   7. Update current distance via relative motion
   
3. COMMUNICATION LOSS HANDLING
------------------------------

   Detection Strategy:
   - Followers track lastLeaderHeartbeat timestamp
   - Compare against current time in handleCommLoss()
   
   Loss Thresholds:
   - WARNING (5 seconds): Increase gap to T_GAP + 2.0 = 2.6s
   - ELECTION (10 seconds): Trigger Bully algorithm for new leader
   
   Fallback Behavior:
   - commLoss flag enables safety mode
   - commLossTimeGap = 2.6 seconds (increased safety margin)
   - Gap policy uses increased gap until communication restored
   - Automatic recovery when leader heartbeat resumes
   
4. BULLY ELECTION ALGORITHM
---------------------------

   Trigger Conditions:
   - Prolonged communication loss (>10 seconds)
   - Follower becomes isolated from leader
   
   Election Process (existing implementation):
   - Highest node ID wins
   - Re-evaluated every 1 second
   - All followers automatically join new leader
   - New leader broadcasts member list to platoon
   
   Integration:
   - handleCommLoss() triggers dynamicLeaderElection()
   - Ensures decentralized recovery without single point of failure
